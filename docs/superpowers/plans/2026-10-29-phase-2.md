# TinySteps Phase 2 implementation plan

User authorized Phase 2, a potato companion, curriculum scheduling, visible release versions, and Phase 2.2 appearance expansion.

## Releases
Current baseline: 1.0.2 (user-provided). Phase 2.1 account foundation: 1.1.0. Phase 2.2 appearance expansion: 1.2.0. Delivered standalone fixes use patch increments; future feature/phase releases use minor increments. Display package version in app footer and Help. Do not bump on every unshipped edit.

## Phase 2.1
- Inspect existing Supabase tables and Google provider without logging credentials or changing existing data.
- Implement PKCE Google sign-in, verified server identity, callback errors, sign-out, protected account views, and account-aware UI.
- Add additive migrations for profiles, preferences and learning data with user-owned RLS policies; verify anonymous, owner, and cross-user access using disposable test identities and clean them up.
- Sync initial preferences, bookmarks and introduction progress. Avoid mixing one user's data into another account. Use server-authoritative version checks, explicit conflicts, and local guest scope.
- Add minimal read-only health RPC; dedicated credential restricted to that RPC for GitHub Actions. No service-role credential in Actions or browser.
- Add independent scheduled/manual keep-alive workflow with bounded retries and safe logs. Verify real execution if GitHub secrets/dispatch access is available; otherwise record the exact boundary.
- Replace the sprout character with an original cute potato. Preserve botanical brand styling.
- Verify real Google OAuth with user interaction; never claim successful sign-in from configured provider alone.

## Phase 2.2
- Extend existing palettes and background scenes, add validated custom colors, immediate previews and account persistence.
- Verify contrast, reduced motion, responsive layout and scene intensity.

## Completion gates
Lint, typecheck, unit tests, build, browser/auth/RLS checks, secret scan, phase notes, master commits/push, no deployment. Record any user-controlled OAuth or Actions blocker honestly. Prepare Codex cloud handoff and stop after local Phase 2; no Phase 3 implementation here.

## Curriculum decision
Deliver all 64 reviewed lessons (8 per existing collection) in Phase 3, before completing timeline and Learning Map links. Phase 4 adds cross-links to room/guide content; Phase 5 release requires all health/safety source reviews to pass. The lesson structure remains Watch, Explore, Practice, Understand, Remember. No fabricated sources or duplicate filler.
